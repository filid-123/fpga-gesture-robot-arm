## 已确认的操作规则

- A：数字 1/2/3 对应红/黄/蓝固定槽位。B：网页按选择顺序把红色方块、橡皮、小圆罐绑定到数字 1/2/3，允许只选其中一至三类。
- 网页负责配置和真实状态；任务由 FPGA 数字手势发起。PALM 确认后递到手中；FIST 为普通取消，按已执行路径返回。任务启动后不能改模式或映射。
- A、B 保留各自 HOME。网页“确认并锁定配置”在需要时执行固定空夹爪过渡，显示切换中；收到到位和配置读回后生效。A↔B 过渡各约 1.56 秒规划时间，不包含通信时间。
- A、B **共用同一块红色方块**。A 交付后 B 会把该红块识别为待补回；B 交付后 A 红槽标空。原位是 A 红槽时，B 复用 A 的已验证取放轨迹，并在首尾接 B HOME 过渡；B 从其他允许位置抓取红块时，B 补回仍回到那次冻结的原位。A 补回则回 A 红槽并清除旧的 B 红块待补回记录。
- 若红块仍在 A 红槽以外的桌面上，切换到 A 时暂不响应数字 1，避免去空的公共点抓取。将红块放回 A 红槽，或放到公共点后，重新锁定 A 配置，再做数字 1。黄色、蓝色不受影响。
- 公共补回点为桌面物品中心 `(300,200,height/2)` mm。交付后由人把物品放到该点，原槽/原位保持空，再做同一物品的数字手势。补回无需 PALM。网页换手势顺序不会改变已保存的物品原位。
- 取消在放置开爪提交前沿实际路径退回；开爪已提交后继续退出并回 HOME。取消不是急停。D5 许可、反馈新鲜度、固件错误和通信故障保护保留。六轴到位误差仍按 A 的 `observe_all` 显示，不新增逐点精度门槛。

启动复用 A 的反馈查询与接 HOME 流程；网页锁定之前不接受数字任务。B 可先锁定模式和映射，无需先连接 RGB，也无需三类物品同时在画面里。“刷新”设备列表，选择标定 RGB 相机并连接；实际数字选物时需要该物品的新鲜有效画面。空闲时会预计算已选择物品的路径；复用前核对源位、朝向、抓取配置和共享红块原位类型。每次新源位仍检查源位/连接轨迹，交付族符合绑定的净空证明时快速验证；不符合则回退完整检查，网页显示当前阶段和耗时。

联测顺序建议：A 红块交付→公共点放块→切 B→同一红块补回 A 槽；B 红块交付→切 A→数字 1 补回；B 橡皮/圆罐各做交付、原位补回、夹取前及夹取后 FIST 取消；再做 B 手势重新排序和连续 A↔B 切换。每次回 HOME 后先撤去手势再选物，避免持续数字被误当新任务。共享红块库存、目标原位、最终 HOME 和实际物品状态都要观察。

Ctrl+C 结束并按原 A 路径停止、释放控制权、关闭 backend、恢复传感器与 PS/CPU。故障、D5 丢失、串口异常、卡爪、物品滑落或轨迹异常时停止当前测试；依现场既有断电/许可流程处理，不继续尝试新任务。若 shutdown 明确提示恢复失败，先处理板卡/机械臂状态再重开。程序不把人工观察自动判成成功。

## 速度与日志

两模式统一使用 A 的 T102 `spd=1320/acc=66`、50 Hz、UQ32 五次标量；普通运动上限 72.6°/s、239.58°/s²，近手交付 29.7°/s、130.68°/s²；夹爪和开爪按 A 的各自速度、加速度和 jerk 上限。统一的是速度合同，不是不同路径的总秒数。B 原位精度相关终点和修正保留；新 retiming、连接和联动均需现场验证。

每次新建 `runs/ab_时间/`，包含配置请求/实际应答、源位和方案 SHA、原始任务记录、FPGA 遥测、通信 RTT、视觉各阶段计时、实物观察、片上 trace 与退出恢复结果。运行中可在网页记录实物成功或失败，它只写观察日志，不改库存、不发运动。

```powershell
.\.venv-ab-rocm\Scripts\python.exe -X utf8 -B scripts\summarize_mode_ab_session.py --session runs\你的会话 --out runs\你的指标目录
```

指南五类核心指标的采集入口均已准备：任务成功需人工逐项确认；物理响应 P50/P95/P99/max 需视频/仪器测量；AI 的 batch=1 前处理/推理/后处理会记录，正式 mAP/mIoU 需独立标注集；FPGA 功能和控制时序由片上 trace 与仪器记录；通信记录真实 RTT/错误。专项可选资源时序、持续视觉帧率、稳定运行时长等。缺失的现场数据明确为 NOT_RUN，不由仿真或九张图像回放替代。

独立物理延迟可保存为会话下 `physical_latency.jsonl`，每行包含 `source: "FIELD_MEASUREMENT"`、`sensor_to_physical_response_ms`、`sensor_start_definition`、`physical_response_definition`、`clock_or_video_method`，再运行汇总脚本。请保留原视频、示波器或逻辑分析仪证据。

## 版本与回退

本版 TASK ABI 为 `0x340D`；ARM/PLAN/VIS/MODEL 保持 `0x3101/0x3203/0x3506/0x022267A9`。寄存器协议见 `interface.md`。同次构建的 BIT/HWH/XSA、91 个构建输入、时序和 CDC 证明由 manifest 绑定；全包成员另附 SHA256。

需要重新构建时，在完整包根目录选择未使用的 attempt 名称执行 `python scripts/build_mode_ab.py --attempt a8`，再执行 `python scripts/inspect_mode_ab_impl.py --attempt a8`，即可完成整机实现、独立网表/CDC/时序检查和哈希绑定。两步均不访问板卡。路径表及模型来自随包冻结输入，不能把另一次构建的 HWH 与当前 BIT 配对。

源码/模型/配置/工具及完整板包均应一起使用。不要只复制新 HTML 到旧 B 直串口服务，也不要把新脚本与 A 的 `0x340B` bit 混用。`rollback/` 中保留原 A v0.14.0 ZIP，按其原手册和旧 overlay 完整回退；历史 ZIP 不属于新 AB 实测结果。

提交目录对照：`native_motion/` 对应 FPGA 源码/构建脚本，`hardware/` 对应 BIT/HWH/XSA，`pc/`、`web/`、`scripts/` 对应 host，`model_package/` 对应模型，`evidence/` 对应本版验证，`metrics/` 对应指标口径。联测包外层文件名统一小写，冻结文件内容和历史引用保留原字节，目标环境为 Windows 原生。正式比赛提交前仍需补齐现场证据、独立 AI 效果评测，并移除历史回退 ZIP 等非提交材料。
