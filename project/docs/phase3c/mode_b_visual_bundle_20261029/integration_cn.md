# 从网页接到抓放：文件与接口衔接

本次补包解决网页“缺模型/清单/模块”和当前定位文件缺失。保持已接受的红块、橡皮、药瓶运动实现和局部修正，未改运动模块或发送设备命令。

## 应接的链路

```text
网页显式选相机/照片 → 原分辨率同帧PNG → YOLO六类检测
→ 选中可抓类别的顶面网络 → 当前外参已知高度投影
→ 冻结本次物体中心/朝向/图像/标定SHA
→ 队友统一A/B和有序选择映射 + FPGA确认
→ 原模式B局部运动规划/执行/完成反馈
```

网页已接第一段检测预览，补包提供其原依赖。`replay_mode_b_visual_bundle.py`可复现检测→顶面→毫米，但它是离线回放，输出独立`visual_bundle_metric_replay.v1`，不是能直接提交的`motion_request`。正式桥接需使用当前实时帧，在任务开始时冻结来源和物体，不能用保存图结果驱动实际机械臂。

## 网页与动态编号

网页B最多选3个，编号来自选择顺序。冻结视觉profile里的1红/2橡皮/3瓶用于原独立视觉试验，不能盖掉网页新的顺序。接入方应按`object_class`关联定位与运动适配器，再按设备确认的`gesture_bindings`分配1/2/3。黄/蓝块和剪刀当前有识别，未因网页可选就自动拥有实体抓取适配器；桥接需明确拒绝未支持的抓取请求。

`web/project-console/API_CN.md`有`GET /status`、`POST /mode-lock`草案。已有网页服务可以调用此HTTP接口，FPGA端的统一A/B配置、空闲/revision复核、确认与完成反馈由队友桥接接入；不能只在网页本地切换就显示设备已生效。

## 定位与运动边界

- 检测/顶面保持RAW、不加软件补色、检测0.4/顶面0.7及原形状检查；原冻结19文件全量校验。
- 当前外参从`config/ai_pc/mode_b_visual_current_20261029.json`解析，沿用原同机位1920×1080。原方向检查未全域通过与后来局部实抓接受是不同证据，不能只改接受位混同两者。
- 红/橡皮四角去畸变投影后取物理均值，药瓶盖轮廓投影到46mm平面后拟合圆，不能直接取图像椭圆中心。
- 顶面高度30/15/46与物体中心Z15/7.5/23分开。原相机XY不叠加机械臂局部补偿，补偿留在运动适配器，归还冻结原物体源而非补偿后的端点。
- 红块固定主参考额外向外2mm、圆柱专用X+10mm、橡皮v4 X+13/Y+10mm等是已测局部运动策略，橡皮有25mm邻域约束，不是相机矩阵或全域基座变换。换位置需沿用运动模块原范围检查。

## 队友所需的运动文件在哪里

Giao已发布的`docs/phase3c/mode_b_teammate_handoff_20261028/`包含三类成功路径、参数、源快照和`INTEGRATION_CN.md`；10-29补回包见`docs/phase3c/mode_b_restock_20261029/README_CN.md`。本补包不再复制或覆盖它们。可将视觉输出作为其动态规划输入来源，但必须完成路径迁移、时间/帧新鲜度、任务绑定、完成与夹持信号，不直接把离线观察JSON交给舵机。

## 本轮验证范围

独立解压副本运行网页历史样例真实六类检测，原冻结链全量可读；重跑成功源图，当前外参得到与原实抓定位记录一致的候选。此验证不打开实体相机/串口，不验证FPGA桥接、NPU/ROCm或新抓放。队友下一步可先离线完成接口，再在目标机做NPU/ROCm，最后在当前已验证器材位置下做网页→FPGA→实体联调。
