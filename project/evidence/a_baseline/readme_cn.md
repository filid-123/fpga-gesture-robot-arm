# A模式 v0.14.0 空槽自动复原

本版以用户确认显示正常的v0.13.1为基线，增加公共补料点自动复原。新功能的实板/实物测试为NOT_RUN；正常三色交付、65位置有界Y跟手、速度、无精度到位门槛、Rain模型和1280×720/60Hz HDMI沿用。只使用整个Final包，不能替换旧包中单个脚本或BIT。

## 行为

机械臂在IDLE/HOME、没有持物时，新的手势1/2/3选择对应槽位：有货则按原流程抓取、跟手等待、PALM锁定盲交付；空槽则从公共点取块、放回对应原槽、退爪并回HOME，然后将对应槽标为有货。复原无需PALM，也不跟手。忙碌时不会插入第二个补料任务。完成后同一手势持续保持不会再次触发，必须先出现原来的背景/无手势重新武装，再做数字手势。

公共点是原桌面左下角原点下的木块中心 **D=(300,200,15)mm，即桌面XY=(30,20)cm**。木块仍为同桌面30mm立方体。原槽中心：红(530,250,15)、黄(650,250,15)、蓝(590,320,15)mm。每次在公共点放置与将要选择的数字对应的木块。系统仍识别手势，不验证公共点木块的存在或颜色；库存更新表示动作程序完成，抓住/放稳由现场观察确认。

## 接线与启动

保留现有PYNQ D1/TX→机械臂RX、D0/RX←机械臂TX、共地、已验证3.3V逻辑及原供电。D5在启动前接好，运行中不需要插拔。HDMI仍接HDMI OUT。结束旧程序后，切到本版解压目录，每次换一个新的日志目录：

```powershell
python -X utf8 -B scripts/run_mode_a_restock.py --check-only
python -X utf8 -B scripts/run_mode_a_restock.py --run --monitor-only --seconds 30 --out-dir runs/v014_monitor_01
python -X utf8 -B scripts/run_mode_a_restock.py --run --out-dir runs/v014_flow_01
```

monitor-only进行画面/手势/反馈查询，ARM=0，不启动抓取。闭环入口仍以新鲜反馈接HOME，初始将三槽设为有货。保持原50Hz、spd=1320/acc=66与五次曲线，六轴误差只观察；通信新鲜度、原生关节范围和D5/故障处理保留。普通交付仍要求PRE至少2秒、PALM连续500ms，FIST连续1秒确认。

## 建议按同一进程完成首测

1. 三槽先按原布局摆好。做手势1，按原流程完成红块交付，等回HOME/IDLE，红槽此时显示为空。
2. 把红块中心摆到公共点(30,20)cm，手离开木块；先撤去手势，再做手势1。此时不要按终端r键。
3. 应显示`task_kind=RESTOCK`，HDMI命令“补回红槽”。机械臂取公共点木块，转运回红槽，开爪、抬升、HOME；只有全部完成后红槽才重新可选，`restocked_tasks`增加1。
4. 保持手势1不变时不应再次动作；撤去手势后重新做1，应恢复正常红块交付，并在PRE等待PALM。
5. 用同一方法测黄色/手势2、蓝色/手势3；公共点每次放对应颜色。一次只放一块。动作源和目的槽只由选择的数字与库存决定。

上述过程必须在同一运行进程中连续测试。退出并重新运行会沿用原启动规则重置库存，不能把重启后的库存当作上一次交付的延续。原r/y/b仍保留，用于人工直接补回原槽后的确认；自动复原测试不需要这些键。

## FIST与退出

开爪放回提交前，FIST连续1秒触发取消：尚未夹取则沿退出路径回HOME；已经夹取则沿实际路径逆退，将木块放回公共补料点，再回HOME，对应原槽继续为空。放回原槽的开爪动作一旦开始，则沿用现有释放后的策略：忽略普通取消，完成退爪和HOME，并将原槽设为可选。故障/通信中断不会把未完成的复原标为有货。

Ctrl+C沿用有序停止/释放控制权/导出片上轨迹/恢复相机与PS状态。若出现JTAG Invalid context并标记requires_user_power_cycle，沿用原异常复原方式，不在故障状态下强行续跑。
