# FPGA 开发与交付流程

这是跨项目的工程方法。先读取仓库入口和项目约束，确定当前任务的接口、验收标准、现有修改与可复用证据；项目特有参数和版本制度由项目文档规定。

## 设计前

- 明确时钟/复位域、CDC、端口电平、引脚、AXI 地址/ABI、BRAM 读写延迟、数据位宽和有符号性、吞吐和反压、异常/恢复行为。未知且会改变设计或实物安全的参数先确认。
- 对照整机资源和时序预算选择最简单的可行结构。只实现功能所需的检测与保护；不要为“验证”加入冗余可综合模块。观察点、断言和黄金向量优先放在 Testbench 或软件台架。

## 实现与验证

- 修改 RTL 时同步更新受影响的接口文档和有判据的测试。算术链做位精确对照；FSM 检查完成、超时和恢复；握手/反压、BRAM 冲突和 CDC 按改动风险覆盖。复用现有测试，不为低风险文字改动新增镜像测试。
- 按风险逐级执行：静态检查/软件单测 → 相关模块仿真 → 集成仿真 → 综合/实现 → 时序、DRC 和资源审查 → 板测。报告实际运行命令、工具版本、结果和 `NOT_RUN` 项；不得将 OOC 与整机资源直接相加，也不得把综合通过说成板测通过。
- 对目标器件记录 LUT、FF、BRAM、DSP、目标频率、WNS/WHS、失败路径和余量。资源或时序薄弱时先定位瓶颈再扩功能；修改模型、约束或硬件接口后重新确认相关门槛。

## 上板与版本

- 绑定同次构建的源码/模型/约束、BIT/HWH、报告与哈希；部署到隔离目录，保留回退版本。先只读寄存器/相机/回环及无执行器台架，再按项目许可进入物理动作。
- 每个板测说明环境、供电、是否额外接线及准确引脚/电平、执行命令、预期值与阈值、停止条件、回传证据和复原方式。执行器测试确认限位、许可、急停和空载路径；合成输入、DRY_RUN、板上真实运行、完整实物闭环分开标注。
- 形成最小可复现版本包和日志。失败也保留版本、失败输入、波形/日志、已确认范围及下一次最小复测步骤；不得将计划值写成实测值。
